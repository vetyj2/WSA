v0.2.8 Runtime Bridge Contract

Absorbs the practical UX benefits of a full runtime broker while preserving WSA's public-safe boundary: WSA owns state, hooks, validation, and reports; external runtimes own real actor execution.

actor_state runner-agnostic bridge turn scheduler verification pause no direct runtime execution

Patch Intent

The C option promised a smoother one-command long-loop UX, but it would make WSA own process execution, model routing, and delivery. This patch keeps the bridge path: WSA emits better hooks and preserves better state so Hermes, Codex-style local agents, or another external runtime can execute the real actor calls.

1. Manual TriggerMeetup or Scene starts a bounded run.
2. Prep ReviewContext, selector result, participants, and actor-state seeds are reviewed.
3. Runtime HookWSA emits a focused hook with actor_state and scheduler rationale.
4. CallbackExternal runtime executes the actor turn and writes callback JSON.
5. State UpdateWSA validates output, updates actor_state/floor_state, and opens next hook.
6. Review PackageWSA returns synthesis, provenance, cleanup status, and approval choices.

State Added

  • actor_states per orchestrator run.
  • Actor mandate, scope boundaries, last position, claims, objections, unanswered questions, stance changes, and confidence history.
  • execution_provenance distinguishes local simulation, bridge contract, callback review package, and world mutation status.
  • runtime_bridge_contract declares a runner-agnostic external runtime boundary.

Hook Changes

  • Every bridge hook carries compact actor continuity.
  • Hooks include a scheduler decision explaining why the actor was called.
  • Rounds are documented as reporting units, not equal-airtime guarantees.
  • Prompts instruct the runtime to answer prior objections or unresolved gaps instead of restarting the actor.

Quality Gate

  • Still blocks missing fields, unlabeled uncertainty, and canon mutation attempts.
  • Adds low-value warnings for empty agreement and repeated prior position or answer.
  • Records when deepening or focused retry is recommended.
  • Verification queues can pause risky claims before they influence later turns.

WSA Owns

  • Run state, actor_state, floor_state
  • Hook packet generation
  • Callback path, route, and shape validation
  • Quality-gate records
  • Report and approval package

External Runtime Owns

  • Actor or subagent invocation
  • Model/provider choice and thinking level
  • Docker, Telegram, Codex, or local process control
  • Interrupt execution and cleanup execution
  • User delivery and local approval UX
