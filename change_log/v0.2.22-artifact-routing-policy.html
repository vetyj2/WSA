v0.2.22 Artifact Routing Policy

Adds a read-only pre-write routing contract so Hermes can keep WSA-related artifacts inside managed workspace roots instead of scattering files across runtime-specific locations.

artifact route creation-time policy custom labels source maps no deletion

What Changed

wsa artifact route <artifact_type> recommends where a WSA-related artifact should live before a runtime writes it.

  • Returns classification, path template, cleanup hint, and owner.
  • Routes unknown labels as custom_wsa_artifact rather than failing.
  • Marks external runtime artifacts as source-map-required.

Boundary

This is not an uninstall manifest and not a delete command. It creates no files and performs no cleanup.

Hermes Usage

Hermes can call the route helper before exporting minutes, drafts, runtime delivery files, callbacks, scene artifacts, or custom user outputs. Runtime-owned external files should use a visible wsa/ directory or wsa-... filename when possible.

Managed Flow

1. IntentHermes decides it needs a WSA-related artifact.
2. Routewsa artifact route draft_output --world-id W --session-id S
3. WriteRuntime writes to the recommended managed path or records source-map metadata for external paths.
4. MaintainDiagnostics, migration, archive, and uninstall can reason from bounded locations.

Code Impact

  • New artifact_routing.py module.
  • artifact map now embeds wsa.artifact.routing_policy.v1.
  • CLI adds only one subcommand under existing artifact surface.

Storage Goal

Prefer session/world-scoped directories, keep exports derivable, and make external artifacts visibly WSA-namespaced without letting WSA claim ownership of Hermes memory, skills, or provider files.
