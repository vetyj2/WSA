Compact Hermes Command Surface

This patch prevents WSA from growing a new user-visible shortcut for every capability. It defines a small command surface and lets Hermes route dynamically by workflow, mode, scope, target, and action.

Canonical Entry Points

Startup

Initial world setup. Easystartup is Startup with easy-pick mode, not a separate top-level product surface.

openeasy

Meetup

Non-canon working meetings, worldbuilding candidates, fill work, re-meetups, and decision discussions.

proposal-onlyworking belief

Scene

Scene prep, actor packets, viewpoint filtering, scene data logs, and localized scene reliability.

preplocal scope

Patrol

Periodic or reactive world hygiene, stale work review, unresolved gaps, and queue checks.

reserved route group

Doctor

Install, runtime, update, adapter, template, and contract diagnostics.

readinesspreflight

Database

World data inspection and structural management: worlds, reports, tickets, facts, export, import, migration.

datareview

Routing Hierarchy

Visible Entry Point

Startup, Meetup, Scene, Patrol, Doctor, or Database.

to

Dynamic Route

Hermes resolves workflow, mode, scope, target, and action from the user's natural-language request.

to

Compatibility Command

Existing slash commands and CLI templates execute the actual route without expanding the visible menu.

Registry Changes

Field Meaning
canonical_menu_surface New registry section defining the six visible entrypoints and their internal route groups.
max_visible_entrypoints Set to 6 so menu design resists command sprawl.
compatibility_policy Keeps old commands available while advising Hermes not to expose every route as a top-level menu command.
hierarchy entrypoint -> workflow -> mode -> scope -> target -> action.

Product Boundary

Meetup remains non-canon working belief and intermediate orchestration. Scene remains the reliability layer for scene data logs, localized viewpoint scope, actor/session packets, and scene-prep decisions. Startup and Easystartup remain one entrypoint family.
