v0.2.11 Scene Mode Disclosure

Adds explicit scene mode disclosure and actor contribution accounting so WSA reports do not imply a writing-room line-build session when the run only produced fact-audit, constraint, or synthesis outputs.

version v0.2.11 mode disclosure actor accounting scene start no false consensus

Patch Intent

Users may prefer fact-audit synthesis or writing-room line-build. WSA now records what was requested, how the mode was resolved, and what actors actually contributed. The patch does not complete full line-build execution; it makes the current and future execution modes auditable.

1. User/Hermes InputMode can be explicit, profile-based, inferred, or fallback.
2. Mode DisclosureRun artifact records requested and resolved mode.
3. Actor AccountingCallbacks, rejects, rollbacks, fact-audit signals, co-writer evidence, and synthesizer are counted.
4. Honest ReportReports distinguish synthesis/guardrail runs from true line-build consensus.

Modes

  • auto: Hermes/profile/natural-language resolution, WSA fallback is conservative fact-audit synthesis.
  • fact-audit-synthesis: actors verify constraints and a synthesizer writes or packages the draft.
  • writing-room-line-build: actors propose, validate, reject, retry, and accept beats or lines into a ledger.

Accounting

  • Callback accepted/rejected counts.
  • Rollback/retry event count from rejected callbacks.
  • Fact-audit evidence from source refs, fact fields, dependencies, and conflicts.
  • Actor-authored sentence and adopted proposal counts.
  • Function labels: observer, constraint panel, SQL auditor, co-writer, validator, rollback trigger.

Boundaries

  • WSA still does not execute Hermes actor sessions directly.
  • Writing-room mode is declared and accounted for, not fully implemented as a native line ledger yet.
  • Final reports should say what actors actually did and what was not performed.
