v0.2.13 Mode-Aware Hooks

Hook packets now carry workflow- and scene-mode-specific turn contracts so external runtimes can run narrower, more useful actor calls.

mode-aware hooks turn contracts meetup facilitation fact audit line build external runtime owned

What Changed

Every round prompt packet can include mode_aware_turn_contract, a compact machine-readable instruction layer for the current workflow.

  • Meetup turns ask for constraints, objections, dependencies, or proposal movement.
  • Fact-audit scene turns ask for evidence and deferred/unchecked claims.
  • Line-build scene turns ask for one beat or 1-3 candidate lines plus validator decision.

Quality Gate

Callbacks are still accepted/rejected by required fields and side-effect safety. Mode mismatches now produce warnings for runtime retry/deepening decisions.

  • fact_audit_evidence_missing_for_requested_mode
  • line_build_ledger_missing_for_requested_mode
  • line_build_validation_decision_missing
  • meetup_turn_low_value_or_repetitive

Boundary

WSA still does not execute Hermes or subagents. It emits narrower hooks, validates callbacks, records warnings, and keeps canon mutation behind approval.

  • No Docker, Telegram, provider, or cron ownership added.
  • No DB schema migration.
  • No automatic canon or scene-database write.

Operational Flow

1. Scheduler Chooses why this actor should answer now.
2. Mode Contract Defines turn objective, focus fields, success criteria, and forbidden drift.
3. Prompt Packet Hermes receives the task with the exact bounded turn contract.
4. Callback Gate WSA records acceptance, mode warnings, evidence, ledger entries, and review package.

Why It Matters

This closes the gap between “mode was selected” and “the runtime was told what that mode actually requires this turn.”

  • Less generic actor output.
  • Better bridge diagnostics for Hermes.
  • Clearer report provenance for users.
