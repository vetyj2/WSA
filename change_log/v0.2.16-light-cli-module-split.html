v0.2.16 Light CLI Module Split

Separates report/review cleanup and artifact-map CLI handlers from the main parser module without changing command behavior.

module split behavior preserved report handlers artifact handlers no new runtime

What Changed

The parser stays in src/wsa/cli.py, but operational handlers now have clearer landing zones.

  • src/wsa/cli_reports.py owns report list, triage, rejection, and callback archive handlers.
  • src/wsa/cli_artifacts.py owns the artifact architecture map handler.
  • The public commands and output shapes are intentionally unchanged.

Why It Matters

The next features touch exports, diagnostics, uninstall, and maintenance. Giving those areas module boundaries now keeps later patches smaller and easier to audit.

Command Surface

No new top-level command is added. The compact Startup, Meetup, Scene, Patrol, Doctor, and Database model stays intact.

Patch Flow

1. Keep Parser cli.py remains the central command parser and dispatcher.
2. Split Handlers Report and artifact handlers move behind named modules.
3. Preserve Output Existing CLI tests continue to verify behavior.
4. Prepare Growth Export, source-map, uninstall, and maintenance patches get cleaner landing zones.

Boundary

This is maintainability work only. It does not make WSA execute Hermes, mutate canon, or change report cleanup semantics.
