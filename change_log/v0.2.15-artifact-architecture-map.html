v0.2.15 Artifact Architecture Map

Adds a compact directory-base map that separates source-of-truth zones, managed artifact zones, runtime residue, and external artifact boundaries.

artifact map source boundary uninstall prep maintenance prep dry-run default

What Changed

WSA can now print or write manager/artifact_map/artifact_architecture_map.json.

  • wsa artifact map prints the generated map.
  • wsa artifact map --write stores the map in the workspace.
  • Template readiness can create and validate the map.
  • Manager diagnostics can create a missing map with --fix.

Source Zones

The map makes source-of-truth roots explicit before export or cleanup tooling grows.

  • control.sqlite
  • worlds/{world_id}/world.sqlite
  • Startup profiles
  • Orchestrator run JSON
  • Date-scoped session logs

Artifact Zones

Derived outputs are bounded to managed roots where future maintenance can reason about them.

  • Report mailboxes
  • World artifacts
  • Meeting and scene folders
  • Hermes reports outbox
  • Task/callback archives and quarantine

Operational Flow

1. Map Generate the workspace source/artifact boundary map.
2. Diagnose Doctor and manager checks can tell whether the map exists.
3. Export Future report exports can point back to source logs and managed roots.
4. Maintain Future uninstall/prune plans can stay dry-run and source-map driven.

Boundary

This patch does not delete files, move worlds, or generate report exports. It only defines the map that later export, uninstall, and maintenance features should use.
