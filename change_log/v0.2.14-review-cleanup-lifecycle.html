v0.2.14 Review Cleanup Lifecycle

Pending proposal reports, author-review runs, and Hermes callback residue now have a bounded triage and cleanup path with audit artifacts.

review queue cleanup audit callback archive Database surface no canon mutation

What Changed

The existing report command family gained lifecycle tools for live workspace hygiene.

  • wsa report triage WORLD_ID is read-only.
  • wsa report reject-pending WORLD_ID rejects pending proposal reports and review-bound runs.
  • wsa report archive-callbacks WORLD_ID moves callback residue into managed archive storage.

Safety Boundary

The cleanup path is intentionally narrow. It handles proposal lifecycle residue, not world-state rollback.

  • Approved reports are excluded.
  • Canon facts and tickets are not modified.
  • Startup profile and DB schema are not changed.
  • Callback JSON is moved, not deleted.

Hermes Surface

The compact menu stays intact. Review cleanup belongs under Database/Review rather than becoming a new top-level product command.

  • /wsa_review_queue maps to read-only triage.
  • /wsa_review_cleanup requires author approval.
  • Local custom aliases still belong in the user overlay.

Operational Flow

1. Triage Count pending reports, reviewable runs, approved exclusions, and callback residue.
2. Author Intent Hermes briefs the user before mutating proposal state or moving residue files.
3. Cleanup Pending reports and review-bound runs move to rejected; callbacks move to archive.
4. Audit reports/archived/review-cleanup-*.json records what changed and what was excluded.

Why It Matters

Live Hermes sessions can leave proposal and callback residue after experimentation. This patch prevents manual file surgery and keeps update/preflight cleanup explicit.
