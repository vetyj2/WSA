Meetup + Scene Orchestrator Dashboard

This patch turns the orchestrator from one generic simulated meeting path into two explicit workflow entrypoints with visualizable state, turn, prompt, and Hermes hook boundaries.

Patch Intent

Primary Change

2

Official orchestrator entrypoints: meetup and scene_generation.

Execution Boundary

WSA/Hermes

WSA records state, prompts, hooks, quality gates, and approvals. Hermes owns real subagent execution.

Review Surface

HTML

Patch changes are summarized as architecture and workflow diagrams, not only raw code diffs.

Workflow Frames

Meetup

Worldbuilding facts, startup candidates, conflict diagnosis, participant expansion, objections, manager checks, and approval options.

Scene Generation Prep

Scene goal, fact/history/memory filtering, hidden-truth boundaries, actor assignment, multi-role isolation, model/thinking guidance, and prep-complete checks.

Runtime Ownership Flow

Author / Operator

Manually starts a meetup or scene-start run and remains the approval authority.

to
WSA Orchestrator

Creates plan, workflow profile, floor state, turn records, prompt packets, and report package.

to
Hermes Runtime

Adapts hook packets into actual subagent or actor-session calls.

Callback / Output

Hermes returns bounded actor output or manager-check results.

to
Quality Gate

WSA accepts only bounded, uncertainty-labeled, non-mutating outputs.

to
Approval Boundary

Canon, facts, scene drafts, and tickets stay proposal-only until explicit approval.

Module Impact

Area Changed Shape Reason
orchestrator_workflows.py New workflow profile registry for meetup and scene generation. Keeps product process definition separate from run lifecycle IO.
orchestrator_turns.py New pure helpers for floor state, turn records, runtime prompts, and terminal hook packets. Prepares the future next/submit callback loop without bloating the orchestrator core.
autonomous_orchestrator.py Now attaches workflow_profile, floor_state, turn_records, and runtime_hook_packets. Run artifacts can show how the meeting or scene-prep floor is supposed to continue.
hermes_commands.py Adds /wsa_scene_start and expands runtime contract entrypoints. Hermes can present scene prep as a first-class skill without pretending WSA executes subagents itself.
cli.py Adds wsa orchestrator hooks <run_id>. Operators and Hermes wrappers can inspect prompt/terminal hook packets directly.

The orchestrator core was split so turn/hook packet logic lives in a smaller execution-facing module. The next safe split candidates are CLI routing and Hermes registry data, but those should be separate patches.

User-Facing Flow

  • wsa orchestrator run --workflow meetup starts a representative worldbuilding meeting and records proposal-only outputs.
  • wsa orchestrator run --workflow scene_generation --skill scene_start starts scene-prep orchestration before script-like drafting.
  • wsa orchestrator hooks <run_id> --format json exposes Hermes-owned terminal/prompt hook packets.
  • /wsa_scene_start becomes a public Hermes shortcut in the command registry.

Still Not Implemented

This patch does not make WSA call real Hermes subagents. The real runtime loop still needs callback ingestion and resume commands such as orchestrator next and orchestrator submit. The important improvement is that the workflow frame and hook packets are now visible, auditable, and ready for Hermes adaptation.
